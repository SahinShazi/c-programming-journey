# পাঠ ১২: ফরম্যাট স্পেসিফায়ার, অক্টাল/হেক্সাডেসিমাল সংখ্যা ও Unsigned Overflow

## সংক্ষিপ্ত বিবরণ

পাঠ ১১-এ আমরা `short`, `long`, `long long` এবং `signed`/`unsigned` ইন্টিজার টাইপ নিয়ে জেনেছি। এই পাঠে আমরা দেখব:
- প্রতিটি টাইপের জন্য সঠিক `printf` ফরম্যাট স্পেসিফায়ার কী
- অক্টাল ও হেক্সাডেসিমাল সংখ্যা কী, এবং সি-তে এগুলো কীভাবে লেখা ও প্রিন্ট করা হয়
- `unsigned` টাইপে ঋণাত্মক সংখ্যা রাখলে কী অদ্ভুত ফলাফল আসে, এবং কেন

## প্রতিটি ইন্টিজার টাইপের ফরম্যাট স্পেসিফায়ার

পাঠ ০৪ ও ০৬-এ আমরা শুধু `%d` শিখেছিলাম। কিন্তু `short`, `long`, `long long`, এবং তাদের `unsigned` ভার্সনের জন্য নিজস্ব স্পেসিফায়ার আছে:

| ডেটা টাইপ | ফরম্যাট স্পেসিফায়ার |
|---|---|
| `short int` (signed) | `%hd` |
| `int` (signed) | `%d` |
| `long int` (signed) | `%ld` |
| `long long int` (signed) | `%lld` |
| `unsigned short int` | `%hu` |
| `unsigned int` | `%u` |
| `unsigned long int` | `%lu` |
| `unsigned long long int` | `%llu` |

### উদাহরণ

```c
#include <stdio.h>

int main() {
    short int a = 45;
    long int b = 100000;
    unsigned int c = 4000000000;

    printf("a = %hd\n", a);
    printf("b = %ld\n", b);
    printf("c = %u\n", c);

    return 0;
}
```

**কেন এটা গুরুত্বপূর্ণ?** যদি তুমি ভুল স্পেসিফায়ার ব্যবহার করো (যেমন `long`-এর জন্য `%d`), কম্পাইলার হয়তো একটা ওয়ার্নিং দেবে, কিন্তু আউটপুট ভুল বা অদ্ভুত হতে পারে — ঠিক যেমন পাঠ ০৬-এ `float`-এর সাথে `%d` মেশানোর ফলাফল দেখেছিলে।

## অক্টাল (Octal) ও হেক্সাডেসিমাল (Hexadecimal) সংখ্যা

আমরা সাধারণত যে সংখ্যা পদ্ধতিতে গণনা করি, তাকে বলে **দশমিক (decimal / base-10)** — এতে ব্যবহার হয় ০ থেকে ৯। কিন্তু কম্পিউটার সায়েন্সে আরও দুটো সংখ্যা পদ্ধতি খুব প্রচলিত:

| পদ্ধতি | বেস | ব্যবহৃত অক্ষর/সংখ্যা |
|---|---|---|
| অক্টাল (Octal) | ৮ | ০ – ৭ |
| হেক্সাডেসিমাল (Hexadecimal) | ১৬ | ০ – ৯, তারপর A – F |

### সি-তে অক্টাল/হেক্সাডেসিমাল সংখ্যা লেখা

```c
int octalNum = 077;      // সামনে একটা 0 দিলে এটা অক্টাল সংখ্যা হিসেবে ধরা হয়
int hexNum = 0x3FF;      // সামনে 0x দিলে এটা হেক্সাডেসিমাল সংখ্যা হিসেবে ধরা হয়
```

- **অক্টাল** লিখতে সংখ্যার আগে একটা `0` বসাতে হয়। যেমন `077`। খেয়াল রাখতে হবে অক্টালে `8` বা `9` অঙ্ক থাকতে পারবে না (কারণ অক্টাল বেস-৮, শুধু ০-৭ ব্যবহার হয়) — `089` এর মতো কিছু লিখলে এটা **ইনভ্যালিড অক্টাল ডিজিট** এরর দেবে।
- **হেক্সাডেসিমাল** লিখতে সংখ্যার আগে `0x` বা `0X` বসাতে হয়। যেমন `0x3FF`।

### প্রিন্ট করার ফরম্যাট স্পেসিফায়ার

| চাও কী | স্পেসিফায়ার |
|---|---|
| দশমিক মান দেখাতে | `%d` |
| অক্টাল মান দেখাতে | `%o` |
| হেক্সাডেসিমাল মান দেখাতে (ছোট হাতের a-f) | `%x` |
| হেক্সাডেসিমাল মান দেখাতে (বড় হাতের A-F) | `%X` |

### সবচেয়ে গুরুত্বপূর্ণ কথা: মেমোরিতে মান একটাই, শুধু দেখানোর ধরন আলাদা

```c
int num = 0777;  // অক্টালে লেখা

printf("Decimal: %d\n", num);   // Decimal: 511
printf("Octal: %o\n", num);     // Octal: 777
```

লক্ষ্য করো — ভেরিয়েবলটার আসল মান কখনো বদলায় না, তুমি শুধু সেটাকে **কোন সংখ্যা পদ্ধতিতে দেখতে চাও** তা বেছে নিচ্ছ `printf`-এর স্পেসিফায়ার দিয়ে। `%d` দিয়ে দশমিকে দেখলে `511`, `%o` দিয়ে অক্টালে দেখলে `777` — কিন্তু ভেতরে মেমোরিতে যেটা আছে, সেটা একই বাইনারি মান।

## Unsigned টাইপে ঋণাত্মক সংখ্যা রাখলে কী হয়?

এটা একটা গুরুত্বপূর্ণ ও প্রায়ই ভুল-বোঝা একটা বিষয়। পাঠ ১১-এ শিখেছি `unsigned` টাইপ শুধু ধনাত্মক ও শূন্য রাখতে পারে। তাহলে এমন কোড লিখলে কী হবে?

```c
unsigned short int x = -2;
printf("x = %hu\n", x);
```

**আউটপুট হবে: `x = 65534`** — `-2` নয়!

### কেন এমন হয়?

কম্পিউটার সব সংখ্যা বাইনারি আকারে সংরক্ষণ করে। ঋণাত্মক সংখ্যা সংরক্ষণ করার জন্য একটা পদ্ধতি ব্যবহার হয়, যাকে বলে **"two's complement"** — এতে সংখ্যার প্রতিটি বিট উল্টো (0 হলে 1, 1 হলে 0) করে তাতে ১ যোগ করা হয়।

যখন তুমি `unsigned` ভেরিয়েবলে `-2` রাখতে বলো, কম্পাইলার `-2`-এর two's complement বাইনারি প্যাটার্নটাই মেমোরিতে বসিয়ে দেয়। কিন্তু `unsigned` টাইপ সেই বাইনারি প্যাটার্নটাকে **"ঋণাত্মক" হিসেবে ব্যাখ্যা করে না** — বরং সেটাকে একটা বড় ধনাত্মক সংখ্যা হিসেবে পড়ে। `unsigned short`-এর জন্য সেই সংখ্যাটা হয় `65534` (কারণ `unsigned short`-এর সর্বোচ্চ মান `65535`, আর `-2` মানে "সর্বোচ্চ মানের ২ কম")।

**সহজ কথায়:** `unsigned` টাইপে ঋণাত্মক মান বসালে প্রোগ্রাম ক্র্যাশ করবে না, কিন্তু একটা অপ্রত্যাশিত বড় ধনাত্মক সংখ্যা পাবে — একে বলা হয় **overflow / wraparound** আচরণ।

## মূল শিক্ষণীয় বিষয়

- `short`, `long`, `long long` এবং তাদের `unsigned` ভার্সনের প্রতিটির নিজস্ব `printf` ফরম্যাট স্পেসিফায়ার আছে (`%hd`, `%ld`, `%lld`, `%hu`, `%u`, `%lu`, `%llu` ইত্যাদি)।
- সি-তে **অক্টাল** সংখ্যা লিখতে সামনে `0` এবং **হেক্সাডেসিমাল** লিখতে সামনে `0x` বসাতে হয়।
- একই সংখ্যা `%d`, `%o`, `%x`/`%X` দিয়ে দশমিক, অক্টাল বা হেক্সাডেসিমাল আকারে দেখানো যায় — মেমোরিতে থাকা আসল মান বদলায় না, শুধু দেখানোর পদ্ধতি বদলায়।
- `unsigned` টাইপে ঋণাত্মক সংখ্যা রাখলে সেটা একটা বড় ধনাত্মক সংখ্যায় "wrap around" করে যায় (two's complement বাইনারি রিপ্রেজেন্টেশনের কারণে) — প্রোগ্রাম ক্র্যাশ করে না, কিন্তু ফলাফল অপ্রত্যাশিত হয়।

## সাধারণ ভুলগুলো

- `long`/`long long`/`unsigned` টাইপের জন্য সাধারণ `%d` ব্যবহার করা, সঠিক স্পেসিফায়ার (`%ld`, `%lld`, `%u` ইত্যাদি) ভুলে যাওয়া।
- অক্টাল সংখ্যায় ভুলবশত `8` বা `9` অঙ্ক ব্যবহার করা।
- `unsigned` ভেরিয়েবলে ঋণাত্মক মান রাখা যাবে বলে ধরে নেওয়া, অথচ সেটা আসলে wraparound করে অন্য একটা বড় ধনাত্মক সংখ্যা হয়ে যায়।

## অনুশীলনী

1. একটা `unsigned int` ভেরিয়েবলে `-1` বসিয়ে `%u` দিয়ে প্রিন্ট করো — ফলাফল কত বড় সংখ্যা আসে দেখো, আর ভাবো কেন এটাই যুক্তিসঙ্গত (হিন্ট: এটা `unsigned int`-এর সর্বোচ্চ মান হবে)।
2. একটা সংখ্যা `100` কে অক্টাল ও হেক্সাডেসিমাল — দুই ফরম্যাটেই `printf` দিয়ে প্রিন্ট করো (`%o` এবং `%x` ব্যবহার করে), এবং দশমিকের সাথে তুলনা করো।
3. `0x1A` সংখ্যাটা `%d` দিয়ে প্রিন্ট করে দেখো এর দশমিক মান কত আসে।
